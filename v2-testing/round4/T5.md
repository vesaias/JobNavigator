`allow_credentials=True`, `allow_methods=*`, `allow_headers=*`.

## 4 · Tracer links

630 links, all active, **0 click events in the DB** before and after this pass, and only
**5 distinct destinations** — all the user's own contact URLs
(`https://linkedin.com/in/…` ×314, `https://viktoresadze.com` ×313, plus three malformed
ones, see R4-T5-12). Enumerating a token therefore reveals nothing new about *where* a
link points; what it buys an attacker is a confirmed `short_id` and an arbitrary number of
fake clicks.

- **Length**: 6 chars ×499, 5 ×129, **2 ×2**. Charset observed: 32 of the 36 possible
  `[a-z0-9]`.
- **Shape**: character-class histogram (`D` = digit, `a` = letter) —
  `DDDDDa` ×490, `DDDDa` ×129, `0a` ×2, and only **8** tokens in the random form
  (`aaaaaa`, `aDDaaa`, `aaaaaD`, …). So **622 of 630 are the deterministic
  `f"{job.short_id}{stub}"` with a one-character stub**, and both 2-char tokens are the
  job-less `0{stub}` fallback. The live token space is effectively
  "a 4–5 digit `short_id` you can read off any other document you were sent, times 26".
- **Random fallback**: `random.choices(ascii_lowercase + digits, k=6)` — 36⁶ ≈ 2.18 × 10⁹
  (~31 bits), drawn from `random` (Mersenne Twister), not `secrets`.
- **Guessing**: 300 random 6-char tokens → **300 × 404**. 240 tokens of the deterministic
  shape `<n><stub>` for n = 1…60 × {li, gh, www, por} → **240 × 404** on this dataset (none
  of them collided with a live token, checked against the DB before requesting). No
  lockout, no delay, no 429 on any of the 540 misses.
- **Replay**: the throwaway link opened **50×** in 0.6 s (80 req/s) → **50 × 302 and 50 new
  `TracerClickEvent` rows**, all in one `ip_hash` bucket, none deduplicated, none rate
  limited. Five more with `User-Agent: Slackbot-LinkExpanding` → 5 more rows, correctly
  flagged `is_likely_bot=true` but **still counted**; `/tracer-stats` does not filter them
  out of its total.
- **Open redirect: none.** `Location` always comes from `TracerLink.destination_url`.
  `?url=`, `?next=`, `?redirect=` on both `/cv/{token}` and `/?cv={token}` are ignored;
  `/cv/https://evil.example` and `/cv/%2f%2fevil.example` → 404.
- **Timing**: valid token median **6.4 ms** (p90 19.8) vs invalid **4.0 ms** (p90 4.4),
  n = 25 each — a 2.4 ms oracle produced by the click-log `INSERT` + `COMMIT`. Immaterial,
  since 302-vs-404 already announces validity.

Written up as **R4-T5-07**.

## Findings

### R4-T5-01 · P2 · The résumé `template` parameter escapes `resume_templates/`
`_render_html()` builds `TEMPLATES_DIR / template_name` from an unvalidated string and only
checks `.exists()`. Proven live, authenticated:

```
GET /api/resumes/<id>/pdf?template=../cover_letter_templates/garamond      -> 200 application/pdf, 51 377 B
GET /api/resumes/<id>/pdf?template=../cover_letter_templates/garamond_alt  -> 200 application/pdf, 48 805 B
GET /api/resumes/<id>/pdf?template=../../backend/resume_templates/inter    -> 200 application/pdf, 182 590 B
GET /api/resumes/<id>/pdf?template=../../../../etc                         -> 500 (dir resolved, no template.html.j2)
GET /api/resumes/<id>/pdf?template=/etc/passwd                             -> 500 (absolute path replaces the base)
```

`pathlib` joins an absolute payload by *replacing* the base, so the reachable set is the
whole container filesystem, not just parents of `resume_templates/`. What saves it today is
that the loader always asks for the fixed name `template.html.j2` — so the impact is
(a) rendering any *other* template tree, proven above, and (b) if a `template.html.j2` ever
lands in a writable directory (`/tmp`, an upload path, a mounted volume), a plain
`FileSystemLoader` + unsandboxed `Environment` renders it, which is Jinja SSTI. The same
value is also writable through `PATCH /api/resumes/{id}` (`template` is in `allowed`), so
it persists into `/preview` and every later render, and the failure mode is a bare **500**
rather than the 400 the "not found" branch intends.
Repro: the three commands above with a valid `X-API-Key`.
Fix: `if template_name not in {t["id"] for t in _discover_templates()}: raise HTTPException(400)`,
in `_render_html` and in the `PATCH` validator. Same one-line check belongs on the cover
letter renderer.
**Status**: fixed — a template name is now a folder name, never a path. `validate_template_name(name, templates_dir)` (`backend/api/routes_resumes.py:196-215`) requires `^[a-z0-9_]+$`, resolves the candidate and demands that its parent *is* the templates directory (catching a symlink inside the tree) and that `template.html.j2` is a real file there; anything else is a **422**, never a 500 and never a filesystem read. It guards every place the value is set or used: `_render_html` (`routes_resumes.py:257`, which is what `/preview` and `/pdf?template=` go through), `POST /api/resumes` (`:642`) and `PATCH /api/resumes/{id}` (`:973`, validated before the first `setattr` so a rejected value cannot be half-applied). The cover-letter side reuses the same function through `_validate_template()` (`backend/api/routes_cover_letters.py:52-56`) on its renderer (`:60`), `POST` (`:169`), `PATCH` (`:200`) and `POST /generate` (`:318`, whose `template` body field is persisted onto the letter). `../`, `../../..`, `/etc/passwd`, `%2e%2e%2f…`, a trailing slash, `.`/`..`, backslashes, a wrongly typed value and a case-variant folder name are all rejected; every discovered template still validates. Regressions in `backend/tests/test_r4_t5.py`: `test_template_name_rejects_anything_that_is_not_a_folder` (17 payloads × both template trees), `test_template_name_rejects_non_strings` (4), `test_template_name_accepts_every_discovered_template`, `test_render_html_rejects_a_traversal`, `test_cover_letter_render_rejects_a_traversal`, `test_pdf_template_query_param_cannot_escape_the_template_dir` (3), `test_patch_resume_rejects_a_bad_template` (also asserts the stored value is untouched), `test_patch_resume_accepts_a_real_template`, `test_create_resume_rejects_a_bad_template`, `test_patch_cover_letter_rejects_a_bad_template`.

### R4-T5-02 · P3 · One response header is the only thing between a stored job posting and the API key
The dashboard keeps the raw API key in `localStorage['jobnavigator_api_key']` (the
`jn_session` cookie holds the same raw key, not a derived token). Every iframe that renders
third-party posting HTML is same-origin, and none of the three call sites is sandboxed in a
way that would stop a script on its own:

- `components/JobFeed.jsx:1301,1309` — `sandbox="allow-same-origin allow-scripts …"`; the
  two tokens together are a documented no-op, the sandbox grants nothing.
- `components/ApplicationBoard.jsx:201` — **no `sandbox` attribute at all**.
- `v2/JobFeed.jsx:1380` (live posting) — `sandbox="allow-scripts allow-same-origin …"`.

Only `v2/JobFeed.jsx:1375` (the cached snapshot, `srcDoc` + `sandbox="allow-same-origin"`,
no `allow-scripts`) stands on its own — and that path ignores the response CSP entirely,
because `srcdoc` documents do not get the endpoint's headers.

Table in §3 is the proof: with `_READER_CSP` present nothing runs (A, C, E); with the header
removed the same markup in the same frames reports `origin: http://caddy`, returns the
plaintext key and reads all of `/api/settings` (B, D, F). Not exploitable today — the
header is set on both `/cached-page` and `/live-page`, and stored HTML is cleaned on the way
in — but a refactor that returns `HTMLResponse` without `headers=_READER_CSP`, or adds
`allow-scripts` to the srcDoc frame, is a full compromise of the dashboard with no other
control in the way.
Fix, in order of value: (1) stop storing the raw key in `localStorage` — issue a session
token from `/api/auth/set-session` and keep only that; (2) drop `allow-same-origin` from
every posting iframe and add an explicit `sandbox` attribute to `ApplicationBoard`;
(3) add `script-src 'none'` to `_READER_CSP` alongside `sandbox`; (4) a regression test
asserting the header on both endpoints.
**Status**: fixed for the v2 frames (item 2), decided against item 1 — `allow-same-origin` is gone from **both** v2 iframes, so the response header is no longer the only control. Cached snapshot (`frontend/src/v2/JobFeed.jsx:1379`): `sandbox="allow-popups allow-forms"` + `referrerPolicy="no-referrer"` — no `allow-same-origin` (a script in stored HTML can no longer reach this origin's `localStorage`, cookies or API) and deliberately no `allow-scripts` either, since row E already proved nothing needs to run in a cleaned snapshot and `srcdoc` carries no response CSP to fall back on. Live posting (`:1390`): `sandbox="allow-scripts allow-popups allow-forms"`.
