# v2 design-consistency pass — plan

Goal: every element of the same kind in the v2 frontend (`frontend/src/v2/`) has identical rest, hover, focus, active and disabled styling, expressed through a small primitive layer and semantic tokens, so that a palette and a font set can be swapped in one place. Scope: **v2 only** (v1 is being replaced). Spacing scale and typography scale stay as they are unless a primitive needs them.

Orchestrator: Fable. Workers: Opus (primitives, replacements), Sonnet (nothing yet — the scan and the checks are scripts). Budget agreed: up to 3–4 M worker tokens. Resume rule: first unticked box. Every stage commits (bare message, never push).

## Verification model (the answer to "is the design still the same?")
Two baselines, taken in D0 before any change, re-taken after every replacement step, both scripts (no agent tokens):
- **Pixel baseline** — `tools/shots.py`: every v2 route (plus one base and one tailored `/v2/resumes/{id}`, one `/v2/cover-letters/{id}`), both themes, 1440×900 and 1024×700, DB at the fixed dump, animations disabled, same fonts. Stored under `v2-testing/artifacts/design/<stage>/`. `tools/shotdiff.py` compares two stages pixel-wise (PIL in the backend container), writes a diff image per changed route and a table of changed pixel counts per route/theme/viewport.
- **Style baseline** — `tools/stylecrawl.py`: for every element on every route, role guess + rest/hover/focus/disabled tuple (background, colour, border, radius, shadow, font family/size/weight/line-height, padding, height). Stored as JSON; `tools/stylediff.py` reports every element whose tuple changed.
- **Expected-diff list** — each replacement step ships `round-design/expected-<step>.md`: the sites the grouping table says will change and the exact before → after values. A diff on the list = the fix working. A diff not on the list = regression → the step is not done. A drifted site the user wants to keep becomes a named variant of the primitive, never an inline exception.
- Final gate: the round-3 smoke script and the two flow groups are re-run once at the end (D6).

## Stages
- [x] **D0 baselines** (Fable, scripts) — fresh DB dump `backups/design_baseline_<date>.dump`; `shots.py` + `stylecrawl.py` on HEAD → `artifacts/design/D0/`; commit the tools (artifacts are gitignored).
- [x] **D1 static scan** (Fable, script `tools/stylescan.py`) — parse every `style={{…}}` object and `className` in `frontend/src/v2/*.jsx`; classify by signature into roles: `btn-primary`, `btn-secondary`, `pill`, `icon-btn`, `row`, `card`, `band`, `input`, `select-trigger`, `menu-item`, `section-head`, `chip`, `tag`, `link`, `modal-panel`, `drawer`, `toast`, `table-head`, `label`, `helper-text`, `unclassified`. Output `round-design/scan.md`: one table per role — distinct signatures × sites (file:line) × hover class — plus an `unclassified` list. This table is the migration list. **User reviews it before D2.**
- [x] **D2 canonical spec** (user + Fable) — one signature per role and state written in `round-design/SPEC.md`; semantic tokens defined on top of the palette in `theme.css` (`--btn-primary-bg/-ink/-bg-hover`, `--btn-secondary-*`, `--row-bg-hover`, `--card-bg/-border/-border-hover`, `--input-bg/-border/-border-focus`, `--menu-item-bg-hover`, `--chip-*`, `--tag-*`, `--modal-bg/-shadow`, `--font-body/-display/-mono`, `--t-11…--t-19` text sizes). Palette tokens keep their names; semantic tokens reference them. Variants the user wants kept are named here.
- [x] **D3 primitives** (Opus, one run) — `frontend/src/v2/ui.jsx`: `Button` (primary/secondary/danger/ghost, sizes, disabled, busy), `Pill`, `IconButton`, `Row`, `Card`, `Band`, `Input`, `Textarea`, `Select` trigger, `MenuItem`, `SectionHead`, `Chip`, `Tag`, `Link`, `ModalPanel` (with `useSnapTop`), `Drawer`, `TableHead`, `Label`, `Helper`. Each reads only semantic tokens; hover/focus via the existing class mechanism in `theme.css` (rules rewritten to the semantic tokens). Keyboard access (`kb()`), `aria-*`, integer line-heights built in. Storybook-like page `/v2/ui` listing every primitive in every state (replaces `/v2/toasts`). Verified by the style crawl on `/v2/ui` matching SPEC exactly.
- [x] **D4 replacements** (Opus, one run per primitive, in this order: Button+Pill+IconButton → Input+Textarea+Select → Row+Card+Band → MenuItem+SectionHead+Chip+Tag → Link+Label+Helper → ModalPanel+Drawer+TableHead). Each run: replace every site the scan lists for that role across all screens, behaviour untouched, then Fable runs `stylescan.py` (0 remaining inline sites for the role), `shots.py` + `shotdiff.py` + `stylecrawl.py` + `stylediff.py` against D0, checks every diff against `expected-<step>.md`, commits. A run that leaves unexpected diffs is fixed before the next primitive starts.
- [x] **D5 lint** (script) — `tools/stylelint.py`: fails on any raw colour (`#…`, `rgb(`), any `fontFamily`/`fontSize` literal, any `borderRadius`/`boxShadow` literal outside `theme.css` and `ui.jsx`; on any `style={{` object that matches a role signature outside `ui.jsx`; on any hover class used on a non-primitive. Run after D4; fix the remainder (Opus, one run).
- [x] **D6 theme proof** (Opus, one run + scripts) — second palette block and second font set in `theme.css` (`[data-theme="alt"]` or a `data-skin` attribute), switch, `shots.py` → every route differs from D0 only where colour/type changed (shotdiff with a colour-invariant mode, or visual review of the diff pairs). Add the System theme mode (SHELL-02) while the theme plumbing is open. Then re-run the round-3 smoke script and flows A/B once; fix regressions; restore the DB.
- [ ] **D7 close** — `v2-testing/REPORT-design.md`: roles, sites migrated, variants kept, diffs accepted, lint state, how to add a theme; HANDOVER updated; commit.
