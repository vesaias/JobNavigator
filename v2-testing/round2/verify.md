## Notes on method
- `zIndex`/`z-index`: rendered inline `style` attributes use CSS's kebab-case (`z-index: 70`), not the JS property name (`zIndex`) — cost one wasted script (item 9/8's search-dialog check) before catching it.
- `text=` locators are substring, case-insensitive, and match every element in the ancestor chain whose text content contains the string — a loose `text=Rotate` matched the preview span `"Set (hidden — rotate to view)"` before `Test scrape`/`Test`/`Undo` cases surfaced the same trap (`⋯Test` and its wrapping `Run … Test …` container both "contain" `Test`). Fix: `get_by_text(x, exact=True)`, or scope to a stable `title=`/class attribute and pick `.last` (innermost) over `.first` when parent and child both match.
- A route handler that calls `time.sleep()` before `route.fulfill()` blocks the *entire* harness (the single dispatcher thread services both the route callback and every other Playwright call), so nothing else in the script can run or observe intermediate state during the sleep — confirmed by three scripts (`v_comp26.py`/`c`/`d`) that measured only post-hang state despite sampling loops. The working pattern used throughout (COMP-26 busy state, R2-H-07 stale-response race, R2-H-01): capture the `route` object in the handler and return immediately *without* fulfilling, do whatever page interaction/observation is needed from the main thread, then call `.fulfill()` on the held route object later.
