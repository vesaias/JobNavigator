# Subproblem 3: Tailor and export application packet

## 1. Goal
Create one fact-constrained Persona resume per queued job without scoring and save a durable, mapped packet under the project.

## 2. Why this step exists
The user needs a directly usable resume while retaining an unambiguous relationship between the job, generated Resume row, and files on disk.

## 3. Files involved
- `backend/api/routes_resumes.py` - allow callers to suppress chained scoring and reuse a PDF rendering service.
- `backend/automation/speedyapply_pipeline.py` - process queue items, validate output, and export packets.
- `backend/automation/application_packets.py` - perform safe atomic directory and index writes.
- `backend/tests/test_application_packets.py` - verify mapping, safe paths, retries, and no-score behavior.

## 4. Exact changes
- Add an internal tailoring option that forces scoring off without changing manual tailoring defaults.
- Use Persona as the configured source and a prompt that excludes speculative suggested bullets and preserves immutable facts.
- Validate immutable fields and reject newly invented numeric claims before marking the result ready.
- Extract PDF rendering into a reusable function and verify that generated bytes contain extractable text and a single page.
- Save `resume.pdf`, `resume.json`, `job.md`, and `metadata.json` under a stable date/job directory.
- Atomically rebuild `application-packets/index.csv` from ready queue rows and store the relative artifact directory on the queue item.

## 5. Out of scope
Do not score or automatically revise the resume, generate cover letters, or submit an application form.

## 6. Done condition
A successful worker leaves one linked Resume row and one mapped packet; rerunning it does not call the LLM or create another packet.

## 7. Verification
- Run `pytest backend/tests/test_application_packets.py backend/tests/test_speedyapply_pipeline.py backend/tests/test_routes_resumes*.py` where matching files exist.

## 8. Expected output
An idempotent no-score worker and a project-local application packet with a human-readable CSV index.

## 9. Notes for the next step
Notification code may use `artifact_dir` and the packet metadata to construct the ready email.

## 10. Risks or ambiguity
PDF generation requires Playwright. A multi-page or non-extractable PDF is saved but marked `needs_review`, not `ready`.
