# Subproblem 4: Email, scheduler, API, and settings

## 1. Goal
Run monitoring and preparation independently, notify through Gmail exactly once per stage, and expose configuration and health in the existing app.

## 2. Why this step exists
Long LLM work must not block feed detection, and the user needs immediate external notification plus visible source health.

## 3. Files involved
- `backend/email_monitor/gmail_client.py` and `backend/gmail_oauth_setup.py` - send RFC 2822 email and request send scope.
- `backend/notifier/email.py` - format detected and terminal feed notifications.
- `backend/scheduler.py` - add five-minute polling and one-minute queue-worker jobs.
- `backend/api/routes_apply_queue.py` - expose generic run/status and packet fields while keeping old routes.
- `backend/api/routes_settings.py`, `frontend/src/components/Settings.jsx`, and `frontend/src/components/ApplyQueueModal.jsx` - expose settings, health, and packet paths.
- `docker-compose.yml` and `.gitignore` - persist but do not track generated packets.

## 4. Exact changes
- Add Gmail `send` support using the existing refresh-token flow and a recipient override that falls back to `Persona.contact.email`.
- Send a detected email after preliminary eligibility and a terminal ready/ineligible/needs-review/failed email after processing.
- Record notification timestamps only after Gmail accepts the message; retry unsent state transitions.
- Schedule feed polling every five minutes and queue workers every minute with non-overlapping tracked runs.
- Add `GET /api/job-feeds/status` and `POST /api/job-feeds/run`; keep `/api/apply-queue/run` as an alias.
- Add packet and source fields to ready queue responses and settings for enabled sources, role families, backfill days, interval, recipient, and artifact directory.
- Mount `./application-packets` at `/app/application-packets` and ignore the host directory in Git.

## 5. Out of scope
Do not expose packet files publicly or attach PDFs to email.

## 6. Done condition
Both schedules register, both email stages are idempotent, status reports feed health, and the UI shows the local packet mapping.

## 7. Verification
- Run the Gmail, scheduler, apply-queue route, and settings tests.
- Run `npm run build` in `frontend/`.

## 8. Expected output
A configurable always-on workflow with external notification and visible local artifact paths.

## 9. Notes for the next step
The final step can treat the feature contract as stable and focus on regression coverage and user setup documentation.

## 10. Risks or ambiguity
The current Gmail token is readonly and must be regenerated by the user after deployment. The worker still produces packets if email is temporarily unavailable.
