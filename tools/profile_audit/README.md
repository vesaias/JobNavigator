# Profile audit

A deterministic, dependency-light audit for résumés and cover letters generated by
JobNavigator. It compares the generated text with a source profile and reports
claims that are not supported by the source.

It is intentionally **not** an LLM judge: it is a fast first pass that makes
invented technologies, companies, dates and metrics visible before a human
review.

## Install

```bash
python3 -m pip install -r tools/profile_audit/requirements.txt
```

Only PyYAML is required.

## Usage

```bash
# source profile -> generated text
python3 tools/profile_audit/audit_generated.py \
  --source path/to/source.yaml \
  --candidate path/to/generated.txt \
  --scan-unknown --strict

# generated JSON from the API (resume json_data or a cover letter)
python3 tools/profile_audit/audit_generated.py \
  --source path/to/source.yaml \
  --candidate /tmp/resume.json \
  --job-description /tmp/job.txt \
  --strict

# query the taxonomy
python3 tools/profile_audit/audit_generated.py --query k8s
python3 tools/profile_audit/audit_generated.py --category "DevOps & SRE"
python3 tools/profile_audit/audit_generated.py --list-categories
```

Try the synthetic examples:

```bash
python3 tools/profile_audit/audit_generated.py \
  --candidate tools/profile_audit/examples/generated_bad.txt \
  --scan-unknown --strict
```

## What it reports

- terms present in the candidate but absent from the source, grouped by category;
- terms allowed by the job description (`--job-description`), kept separate;
- metrics (`10+ years`, `2 million`, `40%`) not present in the source;
- companies and dates from candidate experience entries not present in the source;
- category counts and category co-occurrence per sentence;
- optional capitalized tokens that are not in the taxonomy (`--scan-unknown`).

Exit codes: `0` clean, `2` findings with `--strict`, `1` input error.

## How matching works

1. Normalize the text and match aliases from the longest to the shortest, so
   `node.js` is not read as `node` and `postgres` becomes `PostgreSQL`.
2. Canonical terms map to one or more categories in `keyword_taxonomy.yaml`.
3. Co-occurrence is counted per sentence, producing pairs such as
   `Backend + Databases`.
4. Candidate terms are compared with the source set and, optionally, with the
   job description.

Add a technology by editing the taxonomy; no code change is needed.

## Known limits

- It does not understand prose claims without numbers ("led a team"). A later
  semantic pass (LLM or claim extraction) can cover that.
- A term added by the job description is still a claim the candidate must be able
  to defend; the tool separates it but does not decide whether it is true.
- Keep personal source profiles out of the repository; commit only synthetic
  examples.
