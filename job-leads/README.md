# Job Leads 工作台

这里是校招线索核验、岗位筛选和投递状态的统一目录。以后收到截图、转载消息、群聊文字、二维码或零散链接，都按同一套流程处理，不把未经核验的消息直接当成可投岗位。

## 文件说明

- [applications.md](applications.md)：人工可读的投递总表，包括当前状态、每家公司匹配岗位和不投原因。
- [leads.csv](leads.csv)：唯一的结构化线索数据源；一个岗位一行，供后续检索、去重和链接复查。
- [inbox/](inbox/)：待核验的原始截图、文字、二维码和链接说明。
- [archive/](archive/)：旧版本和自动验证产物，仅用于追溯，不再直接编辑。

## 固定处理流程

1. **接收线索**：保存原始截图、链接或转载文字，记录来源和收到日期。
2. **核验消息**：确认公司、招聘批次、面向届别、截止时间和岗位范围是否属实；年份或批次不一致时明确纠错。
3. **寻找官网**：优先使用公司招聘官网、官方 ATS 或官方校招公告。第三方转载只作为线索，不直接作为最终投递入口。
4. **检查入口**：确认链接可访问、仍在招聘、没有跳错公司或旧批次；登录墙、动态页面和二维码要标记复查状态。
5. **筛选岗位**：进入官网读取当前岗位列表，保留可以直接搜索的完整岗位名，不用“后端方向”“软件研发类”之类泛称代替。
6. **匹配简历**：以 `D:\Github\ChineseInternetResume\resume-zh_CN.tex` 为证据，标记为直接、可迁移、相邻、弱或不支持；不虚构模型训练、CUDA、游戏引擎等经历。
7. **给出结论**：每家公司最多保留 Top 3；没有三个合适岗位就少写，不为凑数推荐明显不匹配岗位。
8. **更新记录**：把核验结果写入 `leads.csv`，把具体岗位与已投/不投状态更新到 `applications.md`，原始材料移入归档。

## 核验优先级

`官方岗位详情 > 官方岗位列表 > 官方校招公告 > 校方转载 > 招聘平台/媒体转载 > 群聊或社交平台消息`

如果官网与转载冲突，以官网当前页面为准；如果官网无法读取，则保留不确定性并标记 `needs_review`，不猜测岗位名或截止日期。

## 投递状态约定

- `已投`：已经提交申请；若具体岗位未知，先写 `unknown`，以后补充。
- `待投`：官网、批次和岗位均已确认，等待实际提交。
- `不投`：用户明确放弃，保留原因但不再继续追踪岗位变化。
- `待核验`：只有线索，尚未完成官网与岗位核验。
- `已关闭`：官网明确下线、过期或批次结束。
